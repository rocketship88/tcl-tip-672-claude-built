What the parser does differently

      
Normally $name(index) is an array reference, and the index is parsed as a word that can contain substitutions. When $ is followed by (( (or by ( in the single-paren build) the new branch takes over instead:

      
    
        
  • It scans for the matching ) without parsing or substituting anything inside.
    • 
        
  • It emits one exprsubst token with a single text token holding the raw body.
    • 
        
  • In the default build the trigger is $(( and the body must be followed by )). The scanner ends the body at the first ) that balances the parentheses inside it, and a look-ahead then requires a second ) right after. That is what turns a forgotten opening parenthesis, as in $((1+2)*3) instead of $(((1+2)*3)), into a syntax error instead of a substitution that ends early and leaves a stray ). Try missing paren and typo on both builds.
    • 
        
  • The compiler hands that raw text to the expression compiler, exactly like the braced word in [expr {...}]. So nothing is substituted twice.
    • 
      

    

    

      
Why the scanner is not just "find the next )"

      
A ) can legitimately appear inside the expression: in a braced word, a quoted string, a backslash sequence, or a [command]. The scanner skips each of those as a unit and counts nested parentheses. Try the braces script to see a ) ignored, and runtime to see a bracketed command skipped through a recursive call.

      
Build note: in the default build the test is $((. In the single-paren build it is just $( and there is no look-ahead. Try the single script on both builds.

    

  


  

    
About this page

    
Written by Claude (an AI) for ET. The C excerpts are copied from the modified Tcl trunk (generic/tclParse.c and generic/tclCompile.c) with their real line numbers, and the token lists, bytecode and results are real output from builds of that code (testparser, tcl::unsupported::disassemble). The step-by-step scanner trace is a faithful port of SkipExprSubstScan to JavaScript, grouped so ordinary characters are one step. At the end of each trace the page checks its own result against the real parser's body, and shows a red warning if they differ.

    
It is a teaching model of a proposed change, not reviewed by the Tcl core team. The version line at the top says which copy you are reading.
